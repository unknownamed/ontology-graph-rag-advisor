# Core Prototype 판정 범위

## 완료 대상으로 검증하는 입력

2026 컴퓨터공학과 **단일전공·일반 국내 학생**의 학점 기준과2026 과목표 적용이 확인되고, 전체 이수내역·학생 구분·졸업논문/인증 결과가 구조화 입력에 검증 상태와 확인 입력 ID로 제공되는 경우다. 현재 활성 CRS v4는 영어 면제와 다른 교양 보충을 조건부로 계산하며, 인증은 확인된 최종 통과 결과 또는 PDF상의 확인된 면제 조건을 사용한다. 인증 세부 시험·자격 전체를 직접 계산하지 않는다. 실제 동일·대체 인정 주장이 없는 일반 이수에는 별도 검토 증명 의무를 만들지 않는다.

관련 적용조건을 모두 식별하고 확인된 입력으로 등록 Core 요건을 검사한 경우 `ELIGIBLE_PDF`, `NOT_ELIGIBLE_PDF`, `UNKNOWN`을 구분한다. 재입학·전과·초과학제 등 현재 계산하지 못하는 관련 조건이 명시되면 그 영향 범위를 확인 필요로 표시한다. `coverage_complete`는 세부 인증 전체 계산 완료를 뜻하지 않는다. 합성 fixture의 `VERIFIED`는 실제 학생 자료의 진위 확인을 뜻하지 않는다. [v4 정정 보고서](source_accuracy_corrections.md)를 따른다.

## Core 기능과 검증

- PDF 출처가 있는 전공 43행·교양 280행의 과목 분류 조회, 전공/교양/총학점 계산, 전공필수·교양 필수군·졸업논문/인증 조건, 부족량과 정보 부족을 결정적 코드로 판정한다. PDF 내부 코드 충돌 `GEA8617`은 자동 산입하지 않는다.
- 실제 이수와 추가 이수 가정을 별도로 계산한다. 서버가 허용된 SQLite 그래프 조회와 규칙 엔진을 실행하며, 화면의 관계·규칙·PDF 링크는 반환된 `EvidenceBundle`과 `ExecutionTrace`에서 만든다.
- 한국어 채팅과 로컬 `qwen3:8b`의 검증된 질문 해석·제한된 답변 말투를 지원한다. 모델이 결과 수치·판정을 결정하지 않는다. PDF·DOCX·PNG의 파일 선택→후보 추출→사용자 확인→질문→판정을 브라우저에서 실행했다. 업로드 후보만으로 전체 성적표의 완전성이나 공식 증빙 진위가 확인되지는 않는다.
- `./scripts/demo_core.ps1`은 합성 입력으로 졸업 가능·미충족·정보 부족·가상 이수를 재현한다. `./scripts/serve.ps1 -Port 18473`은 로컬 채팅 화면을 연다.

## Extended Scope: 남은 구현과 외부 자료

- **현재 PDF로 가능한 미구현 범위:** 다른 2026 학과의 과목표와 학과별 요건을 전수 구조화하고 다전공 계산에 연결하는 일은 추가 구현·검증 작업이다. 이를 외부자료 부족으로 표시하지 않는다. 승인 요청서 평가는 별도 평가 경로에서 수행했으며 질문·답변·항목별 결과는 비공개로 유지한다.
- **과거 적용자:** 2006–2025 단일전공 학점표는 조회 가능하다. 해당 연도 개별 과목표·전필·경과조치의 적용 확인과 학생별 적용 증빙이 필요하므로 전체 이수 판정은 보류한다.
- **복수전공·부전공:** PDF 476–477쪽 정책은 조회한다. 다른 2026 학과의 정적 요건은 현 PDF에서 추가 구조화할 수 있지만, 개별 학생의 제2전공 선발연도·인정 결과·전체 이수정보는 공식 학생 자료가 필요하다.
- **동일·대체:** PDF 14쪽의 처리 원칙은 조회한다. 공식 지정 쌍과 학생의 수강·인정 기록이 없으면 개별 인정은 보류한다.
- **원문 충돌:** PDF42·45쪽의 `GEA8617`은 모두3학점이지만 이름·분류가 달라 공식 정정 또는 식별 근거가 필요하다. 42쪽 학점2라는 과거 설명은 v4에서 정정했다.
- **HWP 5:** 실제 표본의 텍스트 추출까지 확인했다. 과목코드가 있는 적법한 HWP 5 표본 또는 작성 환경이 없어 후보→판정 전체 경로는 미검증이다.

위 미확인 항목을 2026 단일전공의 검증된 입력에 임의로 적용하지 않는다. 승인 요청서 평가는 런타임과 분리하며, 기존 10/10은 요약 사실 검사 결과다.

## v2 데모 당시 기준과 B / C 제한 (역사적 기록)

활성 집합은 `ADS-CE-2026-CORE v1`, RuleSet은 `CRS-CE-2026-CORE v2`다. 현재 Core의 19개 실행 Rule·11개 VERIFIED 정책 사실·323개 편성행을 사용한다. 이번 데모 고정은 규칙이나 지원 대상을 추가하지 않는다. 전체 제품의 미완료 상태와 Core 시연 PASS는 구분한다.

| 구분 | 남은 항목 | 안전한 현재 처리 / 필요한 자료 |
| --- | --- | --- |
| Extended 구현 | 타 학과 전수 구조화·다전공 학생 계산 | 현재 PDF의 정책 조회만 제공; 학과별 적재·독립 검증 필요 |
| B: 공식 자료 대기 | 과거 적용자의 전체 규칙, 공식 동일·대체 지정 | 적용 원칙만 조회; 연도별 교육과정·지정표·학생별 인정 기록 필요 |
| B: 학생·운영 증빙 대기 | 졸업인증·논문 최종 승인, 상담 세부 횟수 | 추출을 승인으로 취급하지 않음; 공식 승인·운영지침 필요 |
| B: 수강 가능성 자료 대기 | 다음 학기 개설, 선수과목, 시간표 | 졸업요건상 후보만 표시; 공식 개설표·선수과목·시간표 필요 |
| C: 사람 검토 | 공식 PDF 내부 `GEA8617` 코드 충돌, 출처 충돌·판독 불명확 | 자동 선택하지 않음; 원문 정정·명확한 식별/적용 증거 필요 |
| Extended 형식 검증 | HWP 5의 전체 양성 경로, JPG/WEBP 자료별 추출 품질 | 구현된 파서와 지원 완료를 구분; 적법한 양성 표본 필요 |

평가 답변과 공식 원문의 차이는 `EVALUATION_REFERENCE_HAS_EXTRA_INFORMATION`, `SOURCE_CONFLICT`, `NEEDS_HUMAN_REVIEW`로 평가기에 보존한다. 해당 답변을 새 Rule·별칭·fixture로 공개하거나 반영하지 않는다. B/C 해소 시에도 근거를 검증한 새 RuleSet에서만 반영한다.

현재 언어 처리 제한: 학생 상태 없이 “교양 47학점 취득하면 얼마나 인정돼?”처럼 개인 인정량을 묻는 표현은 학생 입력 안내로 종료할 수 있다. “교양 47학점 취득한 경우 인정 한도는?”처럼 정책 질문임을 명시하면 기존 정책 계산을 조회한다. 이번 작업에서는 해석 범위를 확대하지 않았다. 독립 평가의 `CTX_04`는 누락 학기의 필수과목 미이수를 확정할 근거가 없어 SKIP을 유지한다.
