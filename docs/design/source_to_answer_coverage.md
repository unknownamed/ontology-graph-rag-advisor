## 3. 분류와 계층 표기

분류는 정보 단위별로 부여한다. 한 절의 일부는 연결되고 나머지는 누락될 수 있으므로 복수 분류를 허용한다.

1. 원문 → 답변·근거 연결 및 해당 경로 검증
2. 원문에 있으나 런타임 구조화 데이터 누락
3. 저장됐으나 조회/계산에서 미활용
4. API 데이터는 있으나 자연어/UI에서 해당 의미로 접근 불가
5. 구현의 의미 해석 또는 적용에 오류 위험
6. 원문 자체 불명확/충돌
7. 현재 공식 문서에서 필요한 정보를 확인할 수 없음

아래 연결열은 **구조화 / 그래프 / API·계산 / 자연어 / 답변·UI / 근거 / 자동테스트** 순서다. `○` 연결, `△` 일부만 연결, `—` 해당 의미 누락, `?` 미확인이다. 원문 위치는 별도 열에 기록했다. 색이나 기존 PASS로 전체 완료를 추정하지 않는다.

- **원문:** PDF259 목표/역량, 260 이수체계도/주석, 261 §9·11·12. 권장 교양은 컴퓨터개론1-1, 컴퓨터프로그래밍1-2, 공업수학2-1이다. §12의 1학년1학기 졸업학점 배분 셀은 **17**이다.

- **실제 질문/응답:** Q07 “컴퓨터프로그래밍의 학과 권장 이수학기는?”와 Q37 컴퓨터개론 권장 학년 → 권장3과목 전체만 답변. Q34 “컴공 1학년 1학기 학점배분구조표의 졸업학점은?” → 졸업 총130으로 답변.

### F07. 저장된 교양 영역과 누락된 제한의 학생 접근 — P2 / 분류2·3·4

- **원문:** PDF42–45 확대교양 영역, PDF34 §2-1라 학과별 수강제한.

### F08. 원문 경과조치/재입학 세부는 요약만 남음 — P2 / 분류2·3·4

### F09. 충돌 원인 메타데이터의 학점 오기 — P2 / 분류5·6

- **원문:** PDF42(인쇄34) GEA8617 “수식없는물리로보는세상”, 균형교양, **학점3·이론3·실기0·개설학기2**. PDF45(인쇄37) 같은 코드 “융합프로젝트Ⅰ”, 확대교양, **학점3**, 개설학기 “이룸”. 두 페이지를 이미지로 다시 대조했다.

### F10. 일반 원칙과 실제 지정/승인 구별 — P2 / 분류2·3·4·7

- **원문:** PDF13 §2-3나, 14 §2-5, 476–477 전공 포기·중복·선발.

PDF14에서 **모든 학생에게 동일과목 검토 증빙을 제출하라는 새 의무는 확인되지 않는다.** 이는 현재 구현의 내부 안전 guard(`engine.py:791–816`, `render.py:38`)다. 학생용 의무와 혼동하지 않도록 조건부 검토 필요·원문 의무·내부 적재확인을 구별해야 한다. guard를 무조건 제거하라는 결론은 아니다.

개인 반례는 F01/R01 또는 F10/R02의 **공개 합성 fixture 복사본**을 `student_state`에 넣는다. R03/R04의 새 필드는 계약 밖 조건 탐침임을 유지한다. Rule Engine 직접 호출 결과만으로 E2E 통과를 선언하지 않는다.

## 9. 우선 후속 작업 후보

이번에는 아래 기능을 구현하지 않는다. 다른 학과 확대나 평가 문항 맞춤 작업도 아니다.

1. **P1 — 원문 예외와 적용범위의 판정 경계 재검증(F01·F03·F04).** 영어 면제+다른교양 보충 반례, 명시 연도 미해결 시 수치 차단, 계약 밖 적용조건 수용/coverage 설명을 먼저 다룬다. 정상 경로250 PASS와 별도로 source-semantic 테스트가 필요하다.
2. **P1/P2 — 졸업인증/논문 세부 규칙과 최종 승인 입력을 분리(F02·F04·F10).** 이미 PDF에 있는 인증 정책·면제를 구조화하고, 계산한 세부 조건/제공된 공식 승인/미확인 조건을 표시한다. 내부 동일과목 검토 guard를 모든 학생의 새 의무로 제시하지 않는다. 승인 운영자료가 필요한 부분은 계속 보류한다.
3. **P2 — 학생이 질문한 원문 속성까지 접근 연결(F05–F08·F11).** 저장된 교양 영역·경과 수치와 누락된 권장 시기·시수·기간·수강 정책을 구별해 개선한다. Q34의 배분표/총량 오해와 정책 질문의 불필요한 학생 요구를 막고, GEA8617 충돌 설명 오기(F09)를 먼저 정정할 후보로 포함한다.

보조 문서의 `core_scope.md`에는 아직 v2를 활성 기준처럼 읽을 수 있는 문구가 있다. 활성 런타임은 v3다. 이번 요청의 산출물 범위에 맞춰 기존 문서는 바꾸지 않고 문서 동기화 후보(P3)로 남긴다.

## 10. Builder → Reviewer → Verifier → Quality Gate

- **Builder(감사 수행):** 공식 원문/활성 스냅샷/실제 SQLite/코드의 연결을 조사하고 대표 질문43개를 HTTP로 실행했다. 기능 구현으로 확대하지 않았다.
- **Reviewer(별도 비판 관점):** 기존 테스트의 PASS를 배제하고 신규 반례4개(영어면제 보충, 동일과목 검토 guard 제거, 초과학제 조건 탐침, 장애면제 조건 탐침)를 추가 실행했다. R01은 실제 계약 안의 판정 결함, R03/R04는 계약 밖 적용조건 위험으로 구별했다. 검토 과정에서 GEA8617 충돌 설명의 학점 오기도 원문으로 확인했다.
- **Verifier:**26개 원문 이미지, 323개 그래프 투영값, 37개 실제 payload/trace,250개 회귀를 대조했다. 실행하지 않은 UI/LLM 검증이나 모든 PDF 조건의 검증을 주장하지 않는다. 같은 작업자의 역할별 검토이며 독립 외부 검수로 표현하지 않는다.
- **감사 산출물 Gate: PASS.** 요청된 누락·미활용 분류, source/API 반례, 후속 우선순위와 재현 정보가 기록됐다. **전체 원문→답변 활용 완료 Gate는 미충족**이며, Core의 영어면제 조합 정확성은 후속 수정 전 PASS로 재확정할 수 없다.
- **공개 경계:** 실제 학생 상태/성적표, 승인 요청서 질문·정답, 비공개 로그·DB·인증정보는 이 문서에 포함하지 않는다. 공식 PDF와 v1/v2/v3·판정 코드는 그대로 보존했다.
